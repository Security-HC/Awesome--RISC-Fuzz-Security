## 摘要

Open-source RISC-V GPGPUs such as Vortex ship with directed-kernel regressions but no reference-model checking, functional-coverage model, or sign-off discipline. This paper presents a UVM 1.2 environment and methodology that closes that gap. The environment wraps a bus-master SIMT DUT with role-inverted agents, integrates Vortex's functional simulator (SimX) as a per-configuration golden model over DPI-C, and renders verdicts via two injection-qualified checkers: a bidirectional end-state scoreboard and a per-instruction, per-lane lockstep comparator under five SIMT alignment rules. A two-pass load-value feed makes racy fenceless multi-core programs instruction-granularity verifiable (residual zero over 5,432 retirements), with the interrupt-timing boundary stated. A three-layer coverage model adds, to our knowledge, the first published SIMT functional-coverage layer for RTL GPU verification (divergence depth, bank conflicts, coalescing classes), closing its own layers at 98.1% covergroup-bin / 94.7% total (ISA layer separately: 83.1% bins / 89.3% weighted) under machine-generated, RTL-cited exclusions and a blocking waiver-integrity gate; an unstimulated D-extension elaboration affects no functional bin, only lowering totals. The checking depth surfaced real defects on both sides of the comparison: a JALR LSB ISA deviation, a non-scaling watchdog constant (since fixed upstream), a reset-relay X window found by restoring a silenced assertion, a missing AXI error path proven by fault injection, and a reference-model fetch bug found by the lockstep itself. FuzzGPU (USENIX Security 2026), a concurrent RTL GPU fuzzer on the same DUT, is complementary: fuzzing finds bugs, this methodology quantifies sign-off; both independently found the JALR deviation. All findings ship in an evidence-cited register; every number carries provenance and the method's boundaries are stated rather than waived.

## 研究问题

开源 RISC-V 生态已为标量核积累成熟验证资产，但最复杂的开源处理器类别——GPGPU——没有对应资产：Vortex 只带 directed-kernel 回归与 CI，RTL 级没有 reference-model 检查、没有功能覆盖模型、没有 sign-off 纪律。与此同时 FuzzGPU 证明同一设计空间（Vortex/Ventus）存在真实 bug（20 个未知 bug、10 个 CVE），把该验证缺口从学术不便升级为暴露面。作者因此提出问题：如何为一款总线主设备形态的 SIMT GPGPU 建立工业级 UVM 验证环境与可量化 sign-off 方法，并且这一方法必须同时说明它自己的成立边界。

## Introduction 梳理

研究缺口：标量核有 step-and-compare lockstep、约束随机指令生成器与 ISA 覆盖库（core-v-verif/ImperasDV + RVVI、riscv-dv、DiffTest、OpenTitan），但这些全部针对 scalar（或 SIMD-vector）CPU；GPGPU 一个都没有。既有方法不足的定位：(1) 标量 RVVI 流程从不遇到 SIMT 语义（每 lane 掩码比较、divergence、一条指令多条退休记录），直接套用会产生伪失配；(2) 软件级 GPU 内核验证（GPUVerify、GKLEE）作用于 kernel 源码而非 RTL；(3) 形式化内存一致性工作（RTLCheck、PTX memory model 形式化）到达 RTL 层，但不覆盖 GPGPU 功能 sign-off；(4) FuzzGPU 是同 DUT 上第一个 RTL GPU fuzzer，按设计是 bug 发现引擎——结构覆盖评估、campaign 时间盒、无功能覆盖模型、无 checker 资格证明、无 waiver 纪律。作者把自己的工作定位为互补的另一半：覆盖率量化、checker 非空洞、exclusion 机器生成且过门。贡献（作者明确声称）：1）完整的可配置 UVM 环境（角色反转 agent、DPI-C 逐配置 co-build 的黄金模型、RVVI 风格被动可观测层、双向 end-state scoreboard），任意 clusters×cores×warps×threads 由 plusargs 决定且 elaboration 期参数自检；2）SIMT 的 per-instruction lockstep：五条对齐规则（uuid 键控程序序排序、掩码并集聚合、per-lane 比较作用域、volatile-CSR 排除等），在 5 个配置（6 个程序）上验证 lane-exact；3）有据的两遍 load-value feed，把 racy、无 fence 的多核程序从不可验证变为 instruction-granularity 可验证，并明确给出非同步中断时序处的 soundness 边界；4）三层覆盖模型与诚实闭包，其中原创的 SIMT 微架构功能覆盖层（divergence depth × IPDOM 栈、scratchpad bank conflict、coalescing class）作者称据其所知是 RTL GPU 验证中首个公开发表的功能覆盖层；5）evidence-classified findings register，RTL 与 reference model 双侧缺陷均有 file:line 证据与 disposition。

## 方法

输入生成：(1) 约 30 个定向 kernel，全部用 Vortex 工具链编译、全部与 reference 字节一致；覆盖算术/访存基线、13 类 FPU 操作、TCU WMMA（含多 warp 集合启动）、嵌套 divergence 塔、部分线程掩码下的 barrier、wspawn/tmc sweep、cache MSHR 与访存压力、232KB 文本 kernel、256KB 高熵 store 压力、除法 corner case、SIMT 掩码下的 CSR 写、VOTE/SHFL。(2) 约束随机：riscv-dv 管线 targeting rv32im，含 GPU 专门后处理（machine-mode CSR 剥离、ecall→ebreak）与 end-state 验证；12 个 profile 中 2 个因该 DUT 不可实现被排除（unaligned load/store——无 misaligned 支持；illegal-instruction——无 trap 架构），1 个因与另一 profile 字节级重复被丢弃，余 9 个 generator profile（12 个 seeded instance）；jump-stream 生成被 sanitize 以避开作者自己报告的 JALR-LSB RTL 偏差（R1）。(3) 原创 SIMT 感知生成器 simtgen：随机 C kernel，四轴——divergence（受控分裂深度与不对称掩码的结构化分支树）、memory（stride/scatter/bank-hostile 访问）、barrier topology（单 warp barrier，构造上无死锁，故意不发射 wspawn）、VOTE/SHFL（每程序 8 个 intrinsic）；knob 取自 DUT 自身配置空间（warp/thread 数、LSU coalescer 窗口、local-memory bank 数、IPDOM 栈深），轴分类受 FuzzGPU 启发但未使用其代码。(4) 协议压力：AXI throttle/flood 与 error-injection（+AXI_INJECT_ERR），以及 host/DCR launch-space sweep。谨慎推断：正文未描述在线覆盖率反馈驱动的生成、变异算子或演化式 campaign；simtgen 是按微架构轴定向而非 coverage-guided，我未发现 coverage 作为在线反馈闭环的证据。

反馈/coverage：三层覆盖模型，数据库永不合并。(L1) 第三方 riscvISACOV ISA 层：80 个 active covergroup（RV32I/F/M/Zicsr/Zifencei）；把每个 active lane 当 hart 采样（4,581 样本）与仅 lane 0 采样（1,677 样本）被证明覆盖完全相同的 bin 集——作者用此经验结果论证 ISA 覆盖对 SIMT 轴是盲的，故需要 L2。(L2) 作者贡献的 SIMT 微架构层：divergence_cg（分裂深度 × IPDOM 栈深）、reconvergence、barrier scope/event、tmc/wspawn、lmem_bank_cg（scratchpad bank conflict）、coalesce_cg（合并类别）、cache event、register hazard、beat_cg，以及按执行单元的指令类组。(L3) 系统与协议层：SVA assertion 与 directive 覆盖、AXI 事务空间、DCR/host launch 空间、system-state cross。闭包纪律三条：exclusion 必须结构化、有 RTL file:line 引用、机器生成（示例：一条写响应稳定性断言不可达，因为 adapter 硬连 m_axi_bready = 1'b1，VX_axi_adapter.sv:313），并由 blocking 的 hits-invariant merge gate 校验——每个被 waive 的 bin 在未 waive 的 bank 中必须零命中；该 gate 首次执行即抓到两个真实 waiver 缺陷，其中一个已生效数周；exclusion 按配置键控（global barrier 路径只在单核被排除，≥2 核保留）；reachable-but-unhit 保持红色、绝不 waive；ceiling 必须 root-cause；跨拓扑合并覆盖库被证明无效（instance-set 膨胀会压低按实例百分比）。

Oracle：两个各自独立出 verdict 的 checker，每个都由永久 fault-injection guard 保护。(1) 双向 end-state scoreboard：完成后 DUT 写过的每个字与 SimX 逐字节比较（forward，某个 cache-tier 测试中最多 196,868 字），并且反向检查 SimX 写过而 DUT 从未写的每个字（抓 dropped store）；sub-word store 用 per-byte 有效性掩码；IEEE 舍入合法的 FP 差异做容差比较且有界；只读/GOT 段按区排除。(2) per-instruction、per-lane lockstep comparator：比较 PC、目标寄存器与写入值，只在 active SIMT lane 上比较，四类结局（matched / field mismatch / data mismatch / orphan），两侧都做 drain-empty 检查以捕获丢失或多出的退休。第三条正交门使 run verdict assertion 感知：任何 RTL 运行时断言触发即 fail 并给不同 exit code，失败 run 排除在覆盖合并之外；有一条专门 negative test（故意 misaligned load 且丢弃其值）保持该门诚实——它必须仅通过断言路径失败而 scoreboard 通过。非空洞性由四个 guard 证明：+INJECT_FAULT（翻转 DUT 某个 store 的一位）、+DROP_STORE（抑制一次 DUT store）、+LOCKSTEP_INJECT（翻转一条退休的一位，必须在精确 uuid/PC/lane 被抓）、+DCR_RAL_INJECT（RAL 镜像污染必须被寄存器 checker 抓）；作者还记录了曾抓到一次近乎被接受的空洞门通过（缺失注入 plusarg 时 negative test 报 PASS），并固化为规则：永远验证注入消息，而不是 verdict。超过五条对齐规则之外，comparator 还声明三个有界且记日志的例外类：Rule 4 的 load 值延迟、Rule 5 的 volatile-CSR 排除、仅 fsqrt 的容差（同号、有限、1 ULP 内，每个被容差比较都计数 n_fp_ulp_tol，绝不静默）；其余浮点运算逐位精确，fsqrt 超 1 ULP 或 NaN/Inf 不一致仍 fail。另有一个两遍 reconvergence feed（与 load feed 一起由 +LOCKSTEP_LOADFEED 激活）把被接受的 DUT 平方根结果强制写回 reference 的 FP 寄存器文件并逐位重查下游操作。

五条 SIMT 对齐规则（每条由仿真证据逼出，并各带一条采用者必须重新推导的 DUT 前提）：Rule 1 退休顺序不等于程序序（同一 warp 内 commit arbiter 谁先就绪谁先退，观察到早发射指令晚于两条后发射指令退休；按 per-warp 发射计数器 uuid 排序对齐，前提是运行内不 wrap 的唯一 per-warp 发射计数器）；Rule 2 黄金模型的 uuid 不能作为交叉键（SimX 把退休 uuid 留为 0；对齐键是 per-(core, warp) 程序序，DUT uuid 高位编码 (CORE ID≪NWBITS)+wid，前提是稳定的 (core, warp) 归属键）；Rule 3 一条指令不等于一条退休记录（一条 load 可因 LSU 按内存响应到达逐 lane 提交而出现多条共享同一 uuid、掩码部分重叠的 commit 记录，观察例掩码 0xd 后 0xe；按 uuid 并做线程掩码并集聚合，前提是记录可按 lane 分裂但共享标识符）；Rule 4 load 数据需要自己的抽头与自己的 soundness 过滤（commit arbiter 的 data 字段对 load 是陈旧值，LSU 经异步响应路径写寄存器文件；专用 LSU writeback probe 恢复真实 per-lane 值，但朴素比较不 sound——未初始化栈/局部内存的 load 在两模型间合法不同，在已知良好 kernel 上产生 429 个伪失配；仅当 reference 有效地址落在可验证数据区且黄金值不是初始化 poison 时才比较该 load lane；加过滤后 load 比较精确、默认开启，参考 kernel 上 74 个 in-region lane 被比较、113 个被过滤、0 伪失配；前提是可观测真实 load 值的抽头）；Rule 5 性能计数器 CSR 按定义就是模型发散的（mcycle/minstret/mhpmcounter* 在时序精确 DUT 与功能模型间差一；黄金模型把该计数器范围标为 volatile，comparator 排除其数据但保留 PC 与目标寄存器检查）。

DUT/平台：Vortex，RTL pin 7a52ee5，RV32IMAF，主配置 1CL/1C/4W/4T 加 AXI 接口，QuestaSim 2021.2 仿真。角色反转 agent 架构（GPGPU 是执行程序而非被程序驱动）：host 与 device-configuration-register（DCR）agent 为 active，经平台控制接口驱动 launch 协议（kernel 基址、参数指针、线程数 DCR）；AXI agent 是 active responder / reactive slave，背后是服务 DUT 取指与数据流量的 memory model；memory agent 覆盖非 AXI 部分；passive status agent 观察 busy/completion、已退休指令计数与 PC；virtual sequencer 协调 launch 序列。激励因此是程序（编译好的 ELF），UVM test class 只控制如何 launch/配置/扰动，test 与 program 正交并在 build 层组合。被动可观测层（全部 passive，绝不作为 checker）：绑定到每个 core retire arbiter 的 commit probe，捕获每条退休节拍 {uuid, wid, PC, rd, wb, tmask, per-lane data}；绑定到 load-store slice 的 LSU writeback probe，捕获符号/零扩展后的真实 per-lane load 值；RVVI 风格 interface 与 UVM monitor（经 analysis port 发布合并后的退休流）；供 SIMT 覆盖层的微架构 probe（scheduler、divergence/reconvergence、local-memory bank、memory coalescer、cache-event、register-hazard、commit-beat）。可配置性：单份编译环境由 plusargs（+CLUSTERS/+CORES/+WARPS/+THREADS）决定任何拓扑，接口位宽（如 50-bit memory tag）从 RTL package 推导，elaboration-time assertion 逐参数与 DUT 对照并在不匹配时高调失败；已验证拓扑包括 1CL/1C/4W/4T、1CL/2C、2CL/2C/4W/4T、4C/2W、8C/8W/2T。协议断言：AXI4 SVA 层（约 15–18 条协议性质加 11 条握手稳定性断言）在线检查 burst 合法性、outstanding 计数一致性与背压下信号稳定性，slave 侧 throttle（ready 等待）与 flood（背靠背 R beat）压力模式由 plusarg 门控。作者明确披露：可综合 RTL 树有 18 个本地修改文件（support 与 co-simulation glue 另有修改，环境本身是新代码），因为验证结果是关于特定 artifact 的陈述，upstream/unmodified 无法描述实际所跑内容。

是否需要 golden model：需要，且是方法核心。SimX（Vortex 的功能非时序模拟器，与 RTL 同项目维护）经 DPI-C 链接（simx_init/load/dcr_write/run 加 per-retirement 记录导出），并按配置重建，使 DUT 与 reference 拓扑始终一致；它是 primary golden model 且建模 SIMT。黄金模型崩溃被 signal handler 捕获并映射为 sentinel exit code，因此 reference model 失败被分类（UNVERIFIABLE）而不是崩溃 run 或静默通过。Spike 作为 secondary、independent 的标量 ISS，仅用于离线交叉核对导出的退休 trace 的 base-ISA 子集（warp 0 / lane 0，遇第一个 Vortex 自定义操作即停）：在同一链接 ELF 上，Spike、SimX 与 DUT 恰好退休 11,076 条架构写回，且在每条 PC、目标寄存器与值上一致、零失配，非空洞性由注入一个 fault 并确认其被点名证明。作者明确不夸大该审计的范围：Spike 是标量 ISS，所以只覆盖 warp 0/lane 0 的 base ISA，SIMT 轴没有独立 reference，且这个方向也不会获得一个——后果是 primary golden model 由同一项目维护、必须自身被当作验证目标。

VerDICT 体系：每次 run 给出 PASS、FAIL、UNVERIFIABLE 或（lockstep run）带 instruction-granularity residual 的 END-STATE-VERIFIED；UNVERIFIABLE 是一等公民，带 root-cause 证据分类，绝不强制比较、绝不静默丢弃、绝不计为 pass。

## 实验与评估

Baseline：未提供与 baseline 的定量对比。FuzzGPU（USENIX Security 2026，同一 DUT）以定性互补定位呈现（fuzzing 发现 bug vs 本工作量化 sign-off），并作为 Table I 对照项之一与 core-v-verif/ImperasDV、DiffTest 并列。交叉验证：本文报告为 R1 的 JALR LSB 偏差被 FuzzGPU 独立发现（其 S2、upstream PR #339、CWE-682，位于同项目 ISS 组件），作者据此称偏差本身获得独立佐证（但不是其 RTL 体现的佐证）；FuzzGPU 的 RTL findings X1–X3（PR #356/#358/#359）与本文不重叠，这与不同 pin 与不同 oracle 一致。

实验预算：正文未给 wall-clock、机器时间或 CPU 预算（未确认）。给出的计数：1CL/1C/4W/4T bank 50/50 runs 通过（49 个不同程序，1 个程序在两种 bus mode 下跑两次）；2CL/2C/4W/4T bank 50/50；共享 L2/L3 的第三 bank 51 runs 全通过，总覆盖 93.2%；reset 修复后的 1CL bank（51 runs，2026-08-18）总覆盖同为 94.7%、branch 94.53%、toggle 83.34%（作者标注为 indicative only，因为有两个变量同时变化）；reset 修复后的 2CL bank（110 runs，0 failure）为 93.4% covergroup bins / 94.3% total，取在覆盖模型已增长并完成补救之后。锁步矩阵：6 行（贡献文本称 5 个配置、6 个程序）全部 lane-exact，0 mismatch / 0 orphan，matched writeback 从 855（1CL/1C/2W/2T）到 3,333（2CL/2C/4W/4T）。两遍 load feed 旗舰案例：第一遍 20 个 racy load 级联出 138 条发散退休（5,314 matched、118 data mismatch，共 5,432），第二遍 5,432/5,432 matched、residual 0。ISA 层：全 active lane 采样 4,581 与仅 lane-0 采样 1,677 得到完全相同 bin 集。bank conflict 采样 70,498+ cycles。seed farm：9 个 riscv-dv profile × 10 seed = 90 个额外不同程序（内容哈希验证、全部通过）功能覆盖零增益，除 toggle +0.06% 外每一类逐位相同。simtgen：57 个程序（divergence 与 memory 轴）关闭了 divergence depth-4 与 bank-conflict 两个目标。覆盖样本数：1CL bank 覆盖实例 2,256 个、2CL bank 8,275 个。

统计：报告形式是覆盖百分比与 PASS/FAIL 计数；未提供置信区间、重复实验方差、显著性检验或统计功效分析（未确认）。非空洞性由 fault injection 与注入消息核查来确立，而非统计方法。

周期预算，L2/L3-enabled run 里刷出 22,187 条 false alarm 消息而功能干净（2,789/2,789 lockstep match）。

开销：未给验证环境自身的运行时、仿真时间或内存开销（未确认）。给出的是覆盖层面的结构性约束与负面结果：toggle plateau 被逐子模块 root-cause 到只读 icache 数据端口（VX_socket.sv:106 把 .WRITE_ENABLE(0) 恒置 0；51,340 bins、该子模块 toggle 55.7%、缺失 22,730 bins，占整个 toggle 缺口的 26.4%）与恒定高地址位，且一个对抗性最大熵 kernel 只把聚合 toggle 移动 +0.02%。作者报告修复 R10 后 branch 覆盖从 95.1% 降到 94.5%，并把更低的数当作正确值：relay 之后的模块曾在未知复位周期执行正常操作路径，那些执行被计入已覆盖分支——任何覆盖指标都无法报告它自己的部分覆盖来自不能合法出现的状态。

## 核心贡献

- 一个针对总线主设备 SIMT GPGPU 的完整可配置 UVM 1.2 环境：角色反转 agent（DUT = AXI master，agent = reactive slave）、DPI-C 逐配置重建的功能 golden model、passive RVVI 风格可观测层、双向 end-state scoreboard，拓扑由 plusargs 决定并有 elaboration 期参数自检（作者声称）。
- SIMT 的 per-instruction、per-lane lockstep 方法：五条对齐规则（uuid 键控排序、per-(core,warp) 程序序键、同 uuid 掩码并集聚合、LSU probe + 可验证区过滤的 load 比较、volatile-CSR 排除），每条各消除一类伪失配并各带 DUT 前提；在 5 配置/6 程序上验证 lane-exact（作者实测）。
- 两遍 load-value feed：把 racy、无 fence 的多核程序变为 instruction-granularity 可验证，residual 即 verdict，feeding 不是 suppression（未被 feed 解释的差异仍是硬错），并指出其不动点边界在非同步中断时序与 race 驱动控制流处失效（作者实测 + 作者自陈边界）。
- 三层覆盖模型与闭包纪律：第三方 ISA 层 + 原创 SIMT 微架构层（作者称首个公开发表的 divergence depth × IPDOM 栈、scratchpad bank conflict、memory coalescing class RTL GPU 功能覆盖模型）+ 系统/协议层；机器生成、RTL file:line 引用的 exclusion，blocking 的 hits-invariant waiver 完整性门，reachable-but-unhit 留红，ceiling 必须 root-cause，跨拓扑合并被证明无效。
- checker 非空洞性纪律：每个出 verdict 的 checker 由永久 fault-injection guard 保护，且固化出永远验证注入消息而非 verdict 的规则；覆盖与通过率数字因此作者认为可被直接采信。
- 把 golden model 本身作为验证目标的明确案例：lockstep 发现 reference 的 misaligned fetch bug；reference 的 SIMT-divergent CSR 语义被修正而 RTL quirk 被有意不镜像。
- 一份 evidence-classified findings register：RTL 侧 R1–R10 与 reference-model 侧缺陷，逐条给 file:line 与 disposition；其中 JALR LSB 偏差被并发 FuzzGPU 独立发现、watchdog 宏被上游独立修复，作者如实标注独立佐证的范围边界。
- 覆盖定义自身必须被 RTL 结构验证的实证案例：bank-conflict coverpoint 原先定义在 accepted requests 上，而 local-memory crossbar 每 bank 每周期只允许一个赢家，该 bin 结构性不可能；改到 offered requests 后 bin 变得可达且诚实（169 conflict hits、61 no-conflict、70,460 idle），关闭功劳被明确分给 probe 修复与生成器两方。
- 刺激类型而非刺激数量的负结果：90 个额外 riscv-dv 程序功能覆盖零增益，而 57 个轴定向 simtgen 程序关闭了两个真实目标。

## 与本仓库研究主线的关系

分维度判断：
- 对 Oracle / 覆盖 / 故障注入 / 黄金模型验证维度：直接相关。该文的核心可复用资产是 Oracle 设计（per-instruction per-lane lockstep comparator、四类结局、双侧 drain-empty、五条对齐规则及其 DUT 前提）、覆盖模型构建与 waiver 纪律（机器生成 + RTL file:line 引用 + blocking hits-invariant 完整性门 + 跨拓扑合并无效的实证）、以及 checker 非空洞性（每个出 verdict 的 checker 由永久 fault-injection guard 保护，并固化出核查注入消息而非 verdict 的规则）。这些与处理器验证仓库中覆盖、Oracle、故障注入、Artifact 的主题直接对齐。
- 对多 hart 与内存一致性验证路径：强邻近，方法可迁移，但不能当作 MCM 验证证据。该文确实处理了多核共享内存上的 racy、无 fence 程序（旗舰案例是四核共享内存上单 hart 程序读到一个仍持有 pristine ELF 初值的字，即真实跨核排序 race），给出的技术是两遍 load-value feed 按 (core, warp, PC, occurrence) 键控、第二遍重放 reference 使其共享同一 race 结果、residual 即 verdict。这是 race-outcome 对齐与可验证化技术，不是对内存一致性模型本身的验证：正文没有 litmus test、没有 axiomatic/operational MCM Oracle、没有 coherence 协议规则检查（AXI 侧只有 SVA 协议与握手稳定性 + error 注入，且 Vortex 本身无缓存一致性协议层被验证），也没有按内存序公理（如 store→load、RMW 原子性、fence 语义）构造的可证伪断言。作者自己也把 boundary 说清：race 驱动控制流时两遍 replay 无不动点、residual 15 留红；非同步中断时序 residual 不能到 0、需要 step-follower。因此对多 hart/一致性路径仓库的价值是：一套可直接借鉴的多 hart lockstep 对齐与 racy 程序可验证化工程方法，以及一份明确写出的适用边界，而不是 MCM 验证结果。其弱一致（作者称 weakly coherent、无 fence）与 fenceless 多核程序的设定，与多 hart 验证主题高度对口。
- 对 RTL/SoC 硬件 Fuzzing：仅方法借鉴（就 fuzzing 引擎本身而言）。该文不是 fuzzer：没有变异算子、没有 coverage-guided 在线反馈闭环、没有时间盒 campaign、没有 bug-finding 导向的评估（作者明确把自己定位为 bug discovery 的互补半边：覆盖率量化的 sign-off）。可借鉴之处是生成器设计（simtgen 四轴、knob 取自 DUT 配置空间）、刺激类型而非数量有效的负结果（90 个随机程序零增益 vs 57 个轴定向程序关闭两个目标），以及把 FuzzGPU 作为同期同 DUT 互补工作的定位方式。
- 对微架构安全自动测试：间接。该文是功能验证与 sign-off 导向，没有安全属性、威胁模型或攻击面分析；它提供的是可作为安全测试基础设施复用的 Oracle 资格证明、故障注入 guard 与覆盖模型，以及一条与 FuzzGPU（会发现 bug 与 CVE 的一侧）交叉验证 JALR 偏差的实例。
- 需要提醒的适用性门槛：结果绑定于一个含 18 个本地修改 RTL 文件、单一 RTL pin、单一商用仿真器（QuestaSim，且作者指出 covergroup 在 Verilator 尚不支持）的设置；Table II 原始日志未保留；给定正文未给 artifact 链接。因此复现实验门槛较高，方法论文价值大于即插即用价值。

## 结论

作者结论是：他们把 RISC-V CPU 核的 standard of care——reference-model 验证——带到了 SIMT GPGPU，并给出作者所称 RTL GPU 验证中首个公开发表的 SIMT 功能覆盖模型。环境完整且可配置：总线主设备 DUT 周围是角色反转 agent、per-configuration co-build 的 DPI-C 功能 reference、RVVI 风格被动可观测层、双向 end-state 检查，以及每个 verdict 背后注入证明的非空洞性纪律。lockstep 层贡献五条 SIMT 对齐规则（每条带声明的 DUT 前提）与两遍 load-value feed，把一个架构上未定义的多核 racy 程序从不可验证变为 verified modulo the fed race resolutions（5,432 条退休上 residual 0），同时诚实划定自己在非同步中断时序处的 soundness 边界。闭包方法（机器生成且过门的 exclusion、root-cause 的 ceiling、residual bin 被 disposition 而非 waive）把主配置带到 98.1% covergroup bins / 94.7% total，SIMT 覆盖层由轴定向生成器关闭（divergence 与 bank-conflict 的关闭被折进一个 suite bank；coalescing 的归因更正与途中发现的覆盖模型缺陷都随证据报告）。检查深度在比较的两侧都付出了回报：RTL 侧的 JALR ISA 偏差（有架构后果、被并发 fuzzing 工作独立佐证）、非缩放 watchdog 宏（被上游独立修复）、静默 misaligned 访问破坏模式、缺失的 AXI error path、以及通过恢复被静音的断言而找到的 reset relay X 窗口；reference model 侧的 misaligned-fetch bug（一直在静默丢弃验证结果，由 lockstep 自身发现）。作者认为该方法及其核心教训——reference model 必须与 DUT 一起被验证，覆盖模型必须与两者一起被验证——可直接迁移到其他开源 SIMT 设计，并填补 fuzzing 没有处理的那一半开放 GPU 验证问题。

## 局限性

作者在第 XI 节主动给出 soundness 边界与限制，并在第 XII 节区分前端功能验证与硅 sign-off。
(1) 非同步中断时序：两集群的中断随机测试在同一 load feed 下从 116 条级联发散只收敛到 7、不到 0；residual 被证明是 keying-independent（把 feed 从 per-warp 序数改成 (cid,wid,PC,occurrence) 后 residual 完全不变，排除 feed 对齐伪影）。原因是真实的：时序精确 DUT 与功能模型在不同指令边界取非同步中断，因而受中断影响的路径执行次数不同；任何 load 数据 feed 都无法在中断触发时完成对齐。两遍 trace replay 是 data-only 发散的不动点，非同步输入时序需要 step-follower reference。
(2) 控制流导向的 race：当 racy 载入字节驱动控制流（一个随机跳转测试），pass-2 replay 走不同路径并遇到 pass-1 trace 从未键控的新 racy load（residual 15，其中 13 条为 load 类；post-feed end-state 比较干净）。当 race 喂给分支时两遍 replay 没有不动点，需要迭代（有界不动点）feed 或 step-follower；作者把该 verdict 诚实留红。
(3) 差分测试的结构性盲区：DUT 与 reference 执行同一二进制，因此误编译的 kernel 会被一致地误执行，所有 checker 通过而 kernel 什么都没验证——实测发生于一个 tensor kernel 的编译期 geometry 与 RTL 配置静默不匹配（OBS-028/OBS-029）。等价性只验证模型间不同的部分，所有共享部分（二进制、内存镜像、launch geometry）需要独立断言；作者只关闭了其中一个此类输入（kernel geometry 在 elaboration 断言且注入证明），并把该类别列为开放。
(4) reference-model 独立性：SimX 与 DUT 不独立（同项目协同设计，共享假设可能藏共享 bug）；Spike 审计只覆盖标量子集（warp 0/lane 0）；SIMT 轴没有独立 reference，作者称这是结构性天花板而非未完成任务。
(5) 仿真器依赖：全部结果在一个商用仿真器（QuestaSim）上；作者指出开源仿真 UVM 已快速成熟（近期 Verilator 能 elaborate upstream UVM 2017 并支持约束随机），但 SystemVerilog 功能覆盖（covergroup）在那里仍不支持，因此该方法的 coverage-driven 一半目前不能在开源仿真器上跑；lockstep 与 end-state 检查两半原则上今天就可移植。
(6) D 扩展 elaboration，仅以代码审查定界：主配置 elaborate 了 D 扩展且 MISA 报 D=1（FLEN=64，由 elaboration probe 确认），尽管工具链构建 RV32IMAF、reference 只建模 F——作者称之为 unintentional-by-documentation 的 RTL 事实。覆盖影响由代码审查定界：覆盖模型中唯一 D 专属 bin（float–double 转换）在 RV32 按配置排除（ignore_bins 键控于 XLEN）、ISA 层不编译 D plan、没有激励能发射 D 操作，因此不稀释任何功能 bin；elaborated 但未执行的 D 逻辑只落在代码覆盖分母里，使报告的 total 偏保守（低估 F-only build）、绝不虚高。注意：这是基于代码审查的论证，不是实验关闭。
(7) per-mnemonic 覆盖的 soundness：冻结的 bank 早于几类指令编码别名（4'b1011 同时解码为零条件操作与 EBREAK）这一发现，因此冻结 bank 中的 per-mnemonic ALU 身份不 sound，per-mnemonic 声明只取自补救后的测量。
(8) 结构性覆盖 ceiling：toggle 覆盖因有据可查的结构原因 plateau，作者报告真实值而非 gaming。
(9) 无 trap 架构：异常路径验证在该 DUT 上不可实现，对应 generator profile 被作为不可实现排除而非静默跳过。
(10) verified build 范围：findings 针对单一 RTL pin 的 debug build 陈述；release build 改变 R1 的可见性而非其存在性；Table II 配置矩阵 tally 是文档化结果但其 per-run 原始日志未保留。
(11) 覆盖模型的 provenance：L2/L3 层是作者自撰而非追溯到规范文档，因此 closure 度量的是模型而不是规范。
(12) 作者还披露可综合 RTL 树有 18 个本地修改文件，且第 XII 节明确列出后端/ASIC sign-off（门级仿真、STA、DFT、CDC/RDC、lint、低功耗、物理设计闭包、RTL-网表-后版图等价、硅后回归）全部不在范围内，本文没有任何内容支持可制造性主张。

## 详细阅读分析

- 五条对齐规则是本文最可迁移的工程资产，且每条的动机都来自仿真证据而非推测：Rule 1 由观察到早发射指令晚于两条后发射指令退休逼出（VX_commit.sv:56-71）；Rule 2 由 SimX 把 uuid 留 0 逼出，解法是利用 DUT uuid 高位编码 (CORE ID≪NWBITS)+wid 提供 (core,warp) 归属且不改 RTL；Rule 3 的观察是掩码 0xd 后 0xe 的两条记录共享一个 uuid，作者明确说这与干净的 SIMD-beat 分裂不同，并警告不要按 packet 起止标志聚合；Rule 4 的量化证据是朴素 load 比较在已知良好 kernel 上产生 429 个伪失配，加可验证区过滤后 74 个 in-region lane 被比较、113 个被过滤、0 伪失配；Rule 5 记录 mcycle/minstret/mhpmcounter* 的 off-by-one，并把它归到标准 RVVI exclusion class。
- 覆盖模型的诚实性细节值得单独读：(a) bank-conflict 的 gap 其实是覆盖模型缺陷 OBS-060——coverpoint 定义在 accepted requests 上，而 crossbar 每 bank 每周期只允许一个赢家，因此「同周期同 bank 两个 accepted request」结构性不可能，刻意构造的 bank-hostile 刺激以零冲突证明了这一点；改到 offered requests 后 bin 可达（169/61/70,460），关闭功劳被显式分给 probe 修复与生成器；(b) 早期一份 isolated-merge 报告把 coalescing class 归功于 simtgen，重查后发现现有 coalescer probe 与 kernel 早已覆盖，作者主动更正归因；(c) barrier 与 VOTE/SHFL 两个生成器轴一个 bin 也没关，因为目标已被定向 kernel 完全覆盖，其价值被降级为生成器完整性与 seed 多样性鲁棒性证据——作者不把它算作覆盖进展。
- 「把断言静音」的代价被写成量化案例：库计数器自带的 overflow/underflow 断言在 bring-up 时于 5/15/25 ns 触发，被改写成输入未知即跳过，guard 保留了数月；恢复原断言并 root-cause 后得到 R10（reset relay 的未复位触发器给出 1 周期 X 窗口，if(X) 走 else 分支导致本该被复位保持的逻辑执行正常路径）。修复用 asynchronous-assert/synchronous-deassert 同步器，十二次断言触发变零，对计数器的本地修改被撤销改用未修改的 upstream 文件，51-run 回归在断言武装下通过。作者提炼两条泛化结论：为让 bench 跑起来而禁用的 checker 是发现被静默且开放式丢失的 checker（此处是数月，受影响面是 relay 之后所有模块）；以及修复缺陷会让覆盖数字下降——无法合法出现的状态贡献了覆盖。
- 修复降低覆盖数字的具体证据：branch 从 95.1% 降到 94.5%，因为 relay 之后的模块在未知复位周期执行了正常操作路径且那些执行被计为已覆盖分支；作者报告更低值并标注两个变量同时变化因而该 delta 只是 indicative。
- reference model 作为验证目标的最清晰案例：SimX 按精确字节 PC 取指，对奇数目标跨指令边界读并 abort；作者尝试在 reference 中掩掉 JALR 目标但用证据回退，因为这会把模型固定到规范而非 DUT，并产生 21,968 个幻影 PC 失配。这个「是固定模型到规范还是固定到 DUT」的取舍细节非常值得精读。
- 非空洞性纪律的实操细节：四个 guard 各自必须保持红（+INJECT_FAULT 一位 DUT store、+DROP_STORE 抑制一次 store，两者历史上都在精确地址 0x800075d8 检测到；+LOCKSTEP_INJECT 一位退休必须在精确 uuid/PC/lane 被抓；+DCR_RAL_INJECT 污染 RAL 镜像）；曾抓到 negative test 在注入 plusarg 缺失时误报 PASS 的空洞门，由此固化规则「永远验证注入消息，永不验证 verdict」。更细的量化：in-region load 比较默认开启；fsqrt 的 1 ULP 容差每次都比较并计数 n_fp_ulp_tol；两遍 reconvergence feed 在 fpu_test/fpu_mt 上把 1,675 条 matched retirement 与多线程情形下 4 次 sqrt reconvergence 做到 residual 零。
- 两遍 load-value feed 的证据链：pass 1 记录 20 个 racy load 级联出 138 条发散退休（5,314 matched、118 data mismatch，共 5,432）；pass 2 得 5,432/5,432 residual 0。soundness 依赖一个被声明而非一般性证明的假设——发散 in-region load 是真实 race resolution 而非 DUT load 数据缺陷；旗舰案例中该假设被 trace 分析确认（首次发散 load 读到的字仍是 pristine ELF 初值，无反证）。中断测试下同一 feed 把 116 收敛到 7 而非 0，re-key 后 residual 不变证明不是对齐伪影。
- 刺激的 marginal 图景：90 个额外 riscv-dv 程序（9 profile × 10 seed，内容哈希验证）关闭零个 bin，除 toggle +0.06% 外逐类逐位相同；57 个 simtgen 程序（divergence + memory 轴）关闭 divergence depth-4 与 bank conflict。作者的结论是 stimulus kind 而非 volume 推动该覆盖模型。另注意两个 riscv-dv profile 被作为该 DUT 上不可实现而排除（unaligned load/store 与 illegal-instruction），而不是静默跳过。
- 覆盖方法学上的两个硬结论：(a) 跨拓扑合并覆盖库无效，因为 instance-set 膨胀会压低按实例百分比——所以按配置分 bank；(b) 全 active lane 采样与仅 lane-0 采样覆盖完全相同的 ISA bin 集，这是他们论证 ISA 层对 SIMT 轴盲目、必须另建 L2 层的经验依据。
- 覆盖 ceiling 的 root-cause 方式：toggle plateau 被追到只读 icache 数据端口（VX_socket.sv:106 把 .WRITE_ENABLE(0) 恒置 0）与恒定高地址位，并给出 bin 级数字（51,340 bins、子模块 toggle 55.7%、缺失 22,730 bins、占整个 toggle 缺口 26.4%）；对抗性最大熵 kernel 只移动 +0.02% 聚合 toggle，用来确立 ceiling 是结构性的。
- 与 FuzzGPU 的交叉验证边界写得比较克制：JALR 偏差被两方独立发现（对方在 ISS 组件、PR #339、CWE-682），这佐证偏差但不佐证其 RTL 体现；对方 RTL findings 与本文 disjoint，作者将其归因于不同 pin 与不同 oracle。
- 一个容易被忽略的陷阱：差分测试对激励中的错误结构性盲目——DUT 与 reference 跑同一二进制，误编译的 kernel 被一致误执行而所有 checker 通过；实测案例是 tensor kernel 的编译期 geometry 与 RTL 配置静默不匹配（OBS-028/OBS-029）。作者只关闭了这一个输入（kernel geometry 在 elaboration 断言并注入证明），并把整类问题列为开放。

## 后续核验问题

- 1) 两遍 load-value feed 能否推广成多 hart 验证中的通用 race-outcome 对齐？在含 fence、含原子 RMW、含 release/acquire 的多 hart 程序上，按 (cid,wid,PC,occurrence) 键控是否仍然稳定？作者已证 residual 对 re-key 不敏感，但没有在多 hart 原子/fence 语义上验证，这直接关系它能否用于内存一致性验证而非仅仅 racy 程序可验证化。
2) 作者把非同步中断 residual 需要 step-follower reference 作为结构性边界；那么把 SimX 换成 step-and-compare 的逐指令 stepping follower（如 CPU 侧经典 lockstep 的做法）后，中断测试的 residual 是否能到 0，代价（仿真时间、golden model 改动量）是多少？正文没有给这个替代方案的实验。
3) 覆盖定义自身必须被 RTL 结构验证（OBS-060 bank-conflict 案例）这一教训，能否机械化？即是否存在方法在写 coverpoint 时就用 RTL 结构（如每 bank 每周期单赢家的仲裁不变式）自动判定某些 cross 不可达，从而避免把模型缺陷误判为刺激缺口？
4) 「修复缺陷后 branch 覆盖下降」提示覆盖可被非法状态虚高。是否存在可操作的度量把「来自不能合法出现的状态的覆盖」从分母中剔除（而不是事后人工 root-cause）？例如在未知复位周期屏蔽采样、或把 X 传播纳入覆盖有效性判定？
5) simtgen 的四轴里 barrier topology 与 VOTE/SHFL 没关任何新 bin，作者的归因是已有定向 kernel 完全覆盖。那么在覆盖率尚未饱和的其他 GPU 设计上，这两轴的边际收益是否会不同？需要跨设计的重复实验才能回答。
6) 生成器只在 divergence 与 memory 两轴有收益、90 个随机程序零增益。是否存在第三类「不同 kind」的刺激（特权行为、异常激励、总线错误、随机复位/X 传播、跨配置矩阵广度）能突破当前功能覆盖可达域？作者在第 XII 节把其中若干列为剩余前端工作但未做。
7) 该文与 FuzzGPU 的交叉只发生在 JALR 偏差一个点上，且 RTL findings disjoint。能否设计一个统一实验，把 fuzzer 的 bug 发现信号（结构覆盖、时间盒 campaign）与本文的覆盖率量化 sign-off 信号放进同一 DUT 同一 pin 上做定量比较（例如单位时间发现 bug 数 vs 覆盖闭包进度）？正文只给定性互补，未给这种直接量化对比。
8) 方法的可移植性主张（作者称可迁移到其他开源 SIMT 设计）只在 Vortex 一个 DUT 上验证。对 Ventus 或 GVM 之类的设计，五条对齐规则与 L2 覆盖层的哪一部分需要重新推导（尤其每条规则的 DUT 前提：唯一 per-warp 发射计数器不 wrap、稳定 (core,warp) 归属键、可按 lane 分裂但共享标识的退休记录、可观测真实 load 值的抽头、模型发散 CSR 范围的知识）？
9) 作者披露可综合 RTL 有 18 个本地修改文件，且 release build 会改变 R1 的可见性（而非存在性）。这些本地修改对覆盖闭包与锁步结论的影响是否被量化过？正文只给了定性披露与 R10 一个修复案例，未给出「本地修改 vs 未修改 upstream」的覆盖对比。
10) Artifact 的可复现性：正文称 evidence-cited register 与两个 register 随工作发布，但给定正文没有链接，且 Table II 的 per-run 原始日志明确未保留。若要复用其 Oracle 与覆盖模型，需要哪些额外材料（RTL patch、覆盖模型文件、fault-injection guard 脚本、per-run 日志）才可能复现 98.1%/94.7% 与 5,432 条 residual 0？
11) 该 DUT 无 trap 架构导致异常路径验证不可实现、两个 riscv-dv profile 被排除。在一个带 trap 架构的 RISC-V GPGPU 上，本文的 lockstep 与覆盖方法需要哪些扩展（异常注入、trap 向量覆盖、ISA 层 covergroup 扩展）？
12) 对微架构安全测试而言：本文的 checker 资格证明与故障注入 guard 纪律能否直接充当安全属性 Oracle 的资格化框架（例如证明一个 Spectre 类或 fault-injection 类安全属性 checker 在注入下会变红）？正文没有安全威胁模型，这是一个待做的转换。
